# HawkStars — Application Audit

**Date:** 2026-09-14
**Scope:** Full independent sweep — security, performance & caching, code quality / CI / deploy, SEO, i18n, accessibility.
**Baseline:** working tree as it stands on disk, `main` at `a12ebf95` **plus 14 uncommitted modifications/deletions**. ~52,100 lines across `app/`, `components/`, `lib/`, `payload/`, `utils/`, `i18n/`, `types/`; 673 TS/TSX files; 45 page-builder blocks.

## Method

This audit was built **from the current source only**. The existing `AUDIT.md` (2026-09-10) was excluded from the tree handed to every analysis pass, no prior finding IDs were carried over, and no prior conclusion was reused. For full transparency: its executive summary was read at the outset while scoping this work, which is why the "Fixed since the previous pass" section below can exist at all — but no analysis pass saw it, and every finding here was independently derived and then independently verified against the code. Where a finding here matches an old one, the code produced it again independently — and several old findings are *absent* here because they are genuinely fixed (see "Fixed since the last pass").

Four parallel passes read the code directly. Every finding carries a `file:line` that was actually opened. Twenty-six of the highest-severity claims were then re-verified by hand in a second pass (marked ✓) — including parsing `deploy.yml` with a YAML loader to check the trigger structure, reading the `Contribution` field list against the component that receives it, and character-by-character inspection of the JSON-LD escape.

## Executive summary

This is a well-engineered codebase and the list below is long because the sweep was thorough, not because the work is poor. `strict: true` with no escape hatches, zero `@ts-ignore`/`@ts-expect-error`, seven explicit `any` in the whole tree (five of them unavoidable module declarations), zero `console.log`, two TODOs, a 45-block page builder whose slugs and renderer registry are an *exact* 1:1 set match, and translation files with **perfect key parity** across 18 namespace pairs and 900+ keys. Unusually, the code is commented with its own reasoning — `nginx.conf` explains its cache-lock strategy, `utils/rateLimit.ts` documents the `X-Forwarded-For` bypass it fixes, `app/sitemap.ts` explains exactly which collections carry `_status` and why. A striking number of findings below exist because that reasoning was written down in one place and then not applied in the next one over.

Six things need attention now.

**0. The lint gate is red right now.** `eslint .` exits 1 with 5 errors, all of them in `components/ui/map.tsx` — a file with uncommitted modifications. Four are React Compiler correctness rules (`Cannot access refs during render` ×2, `Calling setState synchronously within an effect` ×2) and one is `This value cannot be modified` on a mutation of Leaflet's `L.drawLocal` object. `tsc --noEmit` passes with **0 errors** and `prettier --check` is clean, so this is the only gate currently failing — but it is enough to fail the `check` job, which means nothing can merge and nothing can deploy until it is resolved. ✓

**1. Donor PII — including donors who asked to be anonymous — is in the public page source.** `payload/collections/Contribution/index.ts:18` locks reads to admins, and the comment above it explains exactly why: *"Contributions hold donor PII… Server-side rendering uses the Local API, which bypasses access control, so restricting this does not affect the public site."* That reasoning holds right up until `app/[lng]/(org)/contribute/page.tsx:226` hands whole contribution documents to `ChairsSection`, which is `'use client'`. Every field of every confirmed chair donation — `donor`, `value`, `extra_info` (a free-form JSON blob of EasyPay customer data), `transaction_key`, `easypay_id`, `payment_method` — is serialised into the RSC payload of an unauthenticated page. The component renders `{contribution.donor}` with no `is_anonymous` check, unlike `components/transparency/OrganizationContributionsTable.tsx:53`, which checks it correctly. For an EU non-profit this is a GDPR exposure, not just a bug. ✓

**2. Unpublished content is publicly readable.** `pages`, `news` and `hawk_projects` all set `read: anyone`/`() => true` with `versions.drafts` + autosave enabled, and `findBySlug` (`lib/payload/queries/helpers.ts:26`) filters on `slug` alone. `draft: false` does *not* exclude a document whose `_status` is `draft` — it only stops Payload merging the newest draft version over the top. So an editor's in-progress page is live at its public URL as they type, and `GET /api/news` lists the drafts directly. The codebase already knows the right pattern: `app/sitemap.ts:35` and both client-side query modules apply `_status: { equals: 'published' }`. It just never reached the collection access rules or the server query layer. ✓

**3. The deploy takes the site down *before* it knows the build works, and nothing checks that it came back up.** `deploy.yml:158-162` runs `pm2 stop` → `pm2 delete` → `rm -rf .next`, and only then installs and builds. `set -e` means any failure in install, build (which needs a 4 GB heap) or `pnpm migrate` exits the script with the process *deleted* from PM2 — `pm2 save` is at line 178, after the failure point, so even a reboot resurrects nothing. The `check` job never runs `pnpm build` at all, so the class of error only `next build` catches is exactly the class discovered on the production box with the site already off. And `app/api/health/route.ts` exists specifically for this — its docstring says it is *"used by the deploy workflow to confirm a freshly started PM2 process is actually serving traffic… before the deploy is considered successful"* — but no workflow step ever calls it. The deploy reports success and posts a green Discord embed the moment `pm2 start` returns. ✓

**4. Two production secrets never reach the server.** `deploy.yml:87-88` exports `PERSONAL_GITHUB_TOKEN` and `NEXT_PUBLIC_CARTO_BASEMAP_KEY` into the step's `env:`, but `appleboy/ssh-action`'s `envs:` on line 95 is a whitelist and stops at `EASYPAY_WEBHOOK_SECRET`. Both arrive empty. The Carto basemap key is written as `NEXT_PUBLIC_CARTO_BASEMAP_KEY=` into production's `.env` on every deploy, so the map basemap has been unauthenticated in production. ✓

**5. A cache keyed on nothing serves the wrong language.** `payload/components/RichText/index.tsx:173` does `blockConvertersCache ??= …` inside a function that takes `lng` — the parameter is ignored after the first call. `RichText` correctly memoises on `[lng]` one line below, but the memo calls into this. In a long-lived PM2 process, whichever locale renders a rich-text block first wins until restart: every block on every `/en/…` page then receives `lng='pt'` and builds its internal links accordingly. Silent, and it will not reproduce in dev. ✓

Nothing else rated Critical. The payment and public-submission flows are genuinely well defended — rate-limited, zod-validated, `is_confirmed` forced false at four independent layers, the EasyPay webhook using `timingSafeEqual` and failing *closed* when its secret is missing, with tests covering all of it.

## Security

### [Critical] SEC-1 — Donor PII, including donors flagged anonymous, is serialised into the public `/contribute` page ✓
- **Where:** `lib/payload/queries/contribution.ts:11-33`; `app/[lng]/(org)/contribute/page.tsx:50`, `:226`, `:234`, `:255`, `:271`; `components/contribute/ChairsSection.tsx:1`, `:84`, `:119`
- **What:** `getChairsContributionsQuery()` calls `payload.find` with `limit: 0` and **no `select`**, returning whole documents. The page groups them and passes them as `currentContributions={loungeChairs}` to `ChairsSections` — and `ChairsSection.tsx:1` is `'use client'`. Every field crosses the server→client boundary into the RSC flight payload of an unauthenticated page: `donor`, `value`, `contribution_date`, `extra_info` (a `json` field holding EasyPay customer data), plus the payment collapsible's `transaction_key`, `easypay_id` and `payment_method`. The component then renders the name unconditionally — `contributor={contribution?.donor}` (`:84`) and `<span>{contribution.donor}</span>` (`:119`) — with **no `is_anonymous` check**.
- **Why it matters:** `payload/collections/Contribution/index.ts:24` deliberately sets `read: authenticatedAdmin`, and the comment above it explains the reasoning: public reads "exposed all of it", and server-side rendering via the Local API is safe *because it stays on the server*. It does not stay on the server here. The Local API defaults to `overrideAccess: true`, so the collection-level rule **and** the field-level `access` block on the payment collapsible (`Contribution/index.ts:115-119`) are both skipped. A donor who ticked "anonymous" has their real name in the page source. `components/transparency/OrganizationContributionsTable.tsx:53` gets this right, which makes the omission look accidental.
- **Fix:** Add `select: { id: true, contribution_type: true, is_anonymous: true, donor: true, contribution_date: true }` to the query, and map to a minimal DTO before the client boundary: `{ id, contribution_type, displayName: is_anonymous ? null : donor }`. Guard `ChairsSection.tsx:84` and `:119` on `is_anonymous`.

### [High] SEC-2 — Unpublished drafts of Pages, News and Projects are publicly readable ✓
- **Where:** `payload/collections/Pages/index.ts:21` (`read: () => true`), `payload/collections/News/index.ts:48` (`read: anyone`), `payload/collections/HawkProject/index.ts:61` (`read: anyone`); drafts enabled at `Pages/index.ts:163`, `News/index.ts:101`, `HawkProject/index.ts:213`; public read path `lib/payload/queries/helpers.ts:26` — `const where: Where = { slug: { equals: slug } };` — and `:35` `draft: opts?.preview ?? false`
- **What:** All three collections enable `versions.drafts` with autosave, so every document carries `_status`. No public read path filters on it. `draft: false` only means "do not resolve the newest draft *version*"; it does not exclude a main document whose `_status` is `'draft'`. So `findPublishedBySlug` returns drafts despite the name, the list queries include them, and the REST API serves them directly: `GET /api/pages?where[_status][equals]=draft`.
- **Why it matters:** Embargoed announcements, unfinished project pages and press releases are readable by anyone who guesses a slug or simply lists the collection. With autosave at a 100 ms interval (PERF-5), a draft is live at its public URL while the editor types. The correct pattern is already used in three other places (`app/sitemap.ts:35`, `lib/payload/client-side/queries/news.ts:36`, `…/projects.ts:19`), and the authenticated preview routes that drafts were *meant* to be reached through are correctly gated.
- **Fix:** Replace `read: anyone` with `({ req: { user } }) => user ? true : { _status: { equals: 'published' } }` on all three, and add the same clause to the `where` in `helpers.ts:26` and `news.ts:34` / `projects.ts` when `preview` is false, so the rendered pages are correct independently of access control.

### [High] SEC-3 — `PAYLOAD_SECRET` in the working tree is 7 lowercase letters ✓
- **Where:** `.env` (value not reproduced — it is 7 characters, all `[a-z]`); consumed at `payload.config.ts:63`, `:213`; production value comes from a GitHub secret at `deploy.yml:69`, `:132`
- **What:** This is the HMAC key Payload uses to sign admin session JWTs. `payload.config.ts:63` asserts only that it is *present*, never that it has entropy.
- **Why it matters:** The keyspace is 26⁷ ≈ 8×10⁹ — recoverable offline in minutes from a single captured token, after which anyone can mint a JWT for any user id, including a full admin. This particular `.env` points at `mongodb://localhost:27017` and `api.test.easypay.pt`, so it reads as a developer file; the risk is that the same string was pasted into the production `PAYLOAD_SECRET` secret. That cannot be checked from the repository.
- **Fix:** Confirm the production secret, and rotate it regardless: `openssl rand -base64 48`. Add a boot assertion beside the others at `payload.config.ts:62-73` that the secret is ≥32 bytes.

### [High] SEC-4 — The activity log leaks donor names and amounts to any authenticated user ✓
- **Where:** `payload/collections/Notification/index.ts:24` (`read: authenticated`); written by `payload/collections/Contribution/hooks/notifyContribution.ts:21-22`, `:32-33`
- **What:** Every contribution create/confirm writes a log row titled `` `Contribution from ${donor}` `` with the message `` `A contribution of €${value} (${doc.contribution_type}) has been received…` ``. The collection is readable by anyone with a session.
- **Why it matters:** `contributions` is restricted to `authenticatedAdmin` specifically to keep donor PII from non-admins. `GET /api/notifications?limit=100&sort=-createdAt` routes straight around that and returns the donor name and exact euro amount of every donation — `is_anonymous` is never consulted by the hook. The dedicated handler `payload/endpoints/getActivityHandler.ts:15` *does* check `isAdmin`, but the plain collection REST endpoint sits alongside it and does not.
- **Fix:** `read: authenticatedAdmin` on `notifications`, and stop embedding the donor name and amount in the log text — `relatedDocId` is already stored, so link to the document instead.

### [Medium] SEC-5 — `contributions` has no `delete` access rule, so any logged-in user can destroy financial records ✓
- **Where:** `payload/collections/Contribution/index.ts:18-28`
- **What:** The access block defines `read`, `create`, `update` and `admin` as `authenticatedAdmin` and omits `delete`. Payload's default for an unspecified operation is `({ req: { user } }) => Boolean(user)`.
- **Why it matters:** A non-admin editor — explicitly forbidden from even *reading* contributions — can `DELETE /api/contributions/<id>` and permanently remove donation records that the public `/transparency` total and the admin dashboard are computed from. `payload/collections/BoardMember.ts:18-23` has the same gap. Note that the comment at `payload/collections/Media/index.ts:14` asserts an unset key "defaults every operation to public" — that is not Payload's behaviour, and that wrong mental model is plausibly what produced this gap.
- **Fix:** Add `delete: authenticatedAdmin` to `Contribution` and an explicit `delete` to `BoardMember`. Then sweep every collection for a complete `{create, read, update, delete}` set rather than relying on defaults.

### [Medium] SEC-6 — Site-wide navigation can be rewritten by any authenticated user ✓
- **Where:** `payload/globals/Header/config.ts:14-16`
- **What:** The global declares only `read: anyone`. `update` is unset and falls back to the authenticated default. Every comparable layout global gates updates on `authenticatedEditor` (`Footer/config.ts:16`, `ProjectsList/config.ts:35`, `EventsList/config.ts:35`).
- **Why it matters:** A low-privilege account can `POST /api/globals/header` and replace every navigation link on every page. Combined with SEC-7 (no scheme validation on link URLs) that is a one-request site-wide redirect or `javascript:` injection reaching every visitor.
- **Fix:** `update: authenticatedEditor` on Header. `MainPage/config.ts:36` and `NewsList/config.ts:30` use bare `authenticated` and deserve the same review.

### [Medium] SEC-7 — CMS-supplied URLs reach `<iframe src>` and `<a href>` with no scheme check
- **Where:** `components/projects/single/ProjectsSingleHero.tsx:155-156`; validator at `payload/collections/HawkProject/HawkProjectPageTab.ts:96-120`; `components/utils/HawkLink/ExternalHawkLink.tsx:19`; link field with no `validate` at `payload/fields/link.ts:100-111`
- **What:** The `videoUrl` validator constrains the value only if it *already* contains `youtube.com`/`youtu.be`; anything else falls through to `return true` at `HawkProjectPageTab.ts:116`. So `javascript:…` is accepted and rendered as an iframe source. `ExternalHawkLink` renders any `link.url` verbatim as an anchor `href`, and the link field carries no validator at all.
- **Why it matters:** `hawk_projects` is `create/update: authenticated`, so any CMS account can plant this. CSP does not help — `next.config.ts:30` includes `'unsafe-inline'` in `script-src`, which governs `javascript:` navigation. The result is same-origin script execution against any visitor, including an admin browsing the site with a 30-day `Lax` session cookie (`Users/index.ts:33`). The right helper already exists — `utils/paths.ts:121` `isHttpUrl`, applied to member submissions via `validateProjectUrl.ts` — it is simply not applied here.
- **Fix:** `validate: (v) => !v || isHttpUrl(v) || 'Must start with http(s)://'` on `HawkProjectPageTab.ts:96` and on `payload/fields/link.ts:100`; guard `ExternalHawkLink.tsx:19`. For the iframe, use a provider allowlist the way `components/Crowdfunding/VideoEmbed.tsx:18-34` already does.

### [Medium] SEC-8 — The login rate limiter runs on `beforeLogin`, which does not fire for failed logins
- **Where:** `payload/collections/Users/hooks/rateLimitLogin.ts:14-27`, wired at `payload/collections/Users/index.ts:49`
- **What:** The hook throws 429 after 10 attempts per IP per 5 minutes, and its comment (echoed in `ONBOARDING.md:60`) describes it as capping attempts "regardless of which account is targeted". Payload runs `beforeLogin` *after* the password has been verified — a wrong password throws `AuthenticationError` before the hook chain is reached.
- **Why it matters:** The control documented as the defence against credential spraying never executes on the attempts it is meant to block. What remains is the per-account lockout (`maxLoginAttempts: 5`, 24 h `lockTime`), which does nothing against one attempt each against 500 addresses. nginx's `limit_req … burst=60` is far too loose to matter.
- **Fix:** Move the limiter in front of the operation — a `beforeOperation` hook checking `operation === 'login'`, or an nginx `limit_req` zone scoped to `location = /api/users/login`. Confirm Payload's hook ordering before rewriting (see *Not verified*).

### [Medium] SEC-9 — `?limit=` on the public list routes returns the entire collection ✓
- **Where:** `app/[lng]/(org)/news/page.tsx:56-58`, `projects/archive/page.tsx:52-55`, `events/archive/page.tsx:50-54`
- **What:** `const limitNews = Number.isFinite(limitParam) ? limitParam : 10;`. `Number('')` is `0`, which *is* finite, so `/pt/news?limit=` yields `limit: 0` — and Payload treats `limit: 0` as unlimited. `?limit=999999` and `?page=-5` are likewise forwarded raw. No clamp exists on this path.
- **Why it matters:** One unauthenticated GET dumps every news article / project / event with relationship population, on a single 2 GB-capped PM2 fork. It is also the easiest way to enumerate the drafts from SEC-2. Because these are page routes, `utils/rateLimit.ts` (which guards `/api/*`) does not apply. Each distinct `limit` value also mints a new `'use cache'` entry against the 50 MB budget at `next.config.ts:59`. `app/api/instagram/route.ts:130-131` clamps correctly — reuse that shape.
- **Fix:** `const limit = Number.isInteger(limitParam) ? Math.min(Math.max(limitParam, 1), 50) : 10;` and the same for `page`, in all three routes.

### [Medium] SEC-10 — Role flags are not enforced on six content collections, and the admin panel is open to any user row
- **Where:** `payload/collections/Users/index.ts:15` (`admin: authenticated`); `Pages/index.ts:19-22`, `News/index.ts:49-51`, `HawkProject/index.ts:62-64`, `HawkEvent/index.ts:38-40`, `ArtCollection/index.ts:18-20`, `Curator/index.ts:17-19` — all `create/update/delete: authenticated`
- **What:** `isAdmin` and `isEditor` exist and are used correctly by `Media`, `Documents`, `Partner`, `Sponsor` and `MemberProject`, but six collections plus three globals gate writes on nothing more than having a session.
- **Why it matters:** There is no contributor or read-only tier in practice — any account is effectively a full content editor able to publish, edit and delete pages, news, projects, events and artworks, and to enter `/admin`. `Users.access.read: authenticated` additionally lets any account enumerate every admin's name and email. It also widens SEC-7's blast radius from "editor" to "any account".
- **Fix:** `authenticatedEditor` for `create`/`update` and `authenticatedAdmin` for `delete` on those six; `Users.access.admin` → `authenticatedEditor`; `Users.access.read` → `authenticatedAdmin` or `{ id: { equals: user.id } }`.

### [Medium] SEC-11 — EasyPay webhook: the secret is absent from the environment, and authorisation notifications are not idempotent ✓
- **Where:** `app/api/easypay/route.ts:29-52`, `:133-158`, `:176-208`; `.env` has no `EASYPAY_WEBHOOK_SECRET`; `.env.example:29`; `deploy.yml:86`, `:150`
- **What:** `isAuthorisedWebhook` is correct — it fails **closed** when the secret is unset and compares with `timingSafeEqual` after a length check. But the variable is simply missing from the working `.env`, so in that environment every EasyPay callback 401s. Separately, `handleAuthorisationNotification` unconditionally `payload.create`s a contribution on every authorisation notification with no lookup on `notification.key`, while `POST` deliberately returns `200` on every error path so retries are absorbed silently. The sibling path `updateContributionStatus` (`:184`) *does* query by `transaction_key` first.
- **Why it matters:** With the secret unset, no donation is ever marked `is_confirmed`, so `/transparency`'s public total and the donor wall permanently under-report — a reconciliation failure visible only as a Sentry warning. With it set, a retried or duplicated callback inserts a **duplicate** `Contribution`, and since the public total sums `value` over confirmed rows, the published figure over-reports. Both directions are wrong on a page whose entire purpose is financial transparency.
- **Fix:** Set `EASYPAY_WEBHOOK_SECRET` in every environment and assert it at boot alongside the others. In `handleAuthorisationNotification`, `payload.find({ where: { transaction_key: { equals: notification.key } }, limit: 1 })` first and `update` when a row exists. Add a unique index on `transaction_key`.

### [Medium] SEC-12 — CSP `script-src` allows `'unsafe-inline'`, which is what makes SEC-7 exploitable
- **Where:** `next.config.ts:28-45`, specifically `:30`
- **What:** `script-src 'self' 'unsafe-inline'` (plus `'unsafe-eval'` in dev), no nonce, no hashes. `frame-src` includes a bare `*.google.com`; `img-src` allows all of `https:`. The trade-off is documented in the file (nonces are incompatible with PPR / `cacheComponents`) and the reasoning is sound as far as it goes.
- **Why it matters:** The policy provides no XSS containment for the defects that actually exist here. `'unsafe-inline'` permits `javascript:` URL navigation, so SEC-7 executes.
- **Fix:** Given nonces are off the table, accept that CSP is not the mitigation and fix the injection sinks directly. Separately, tighten `frame-src` to the exact Google hosts embedded and narrow `img-src` from `https:` to the four hosts already listed at `next.config.ts:63-78`.

### [Medium] SEC-13 — `/api/translate` documents "requires an authenticated admin user" but only checks that a user exists
- **Where:** `payload/endpoints/translate.ts:16` (doc) vs `:22` (code)
- **What:** `if (!user) return Response.json({ error: 'Unauthorized' }, { status: 401 });` — no `user.isAdmin`. `payload/endpoints/getActivityHandler.ts:15` and `sumContributions.ts:13` both check properly.
- **Why it matters:** Any authenticated account can drive unbounded outbound POSTs (20 KB per request) to the translation backend. The comment asserting a guard that is not there is the worse half — anyone auditing access control will read it and move on.
- **Fix:** `if (!user || !user.isAdmin)`, or correct the docstring if editors are meant to have it.

### [Low] SEC-14 — `BreadcrumbJsonLd` is the one JSON-LD builder without the `<` escape
- **Where:** `components/seo/JsonLd.tsx:84`
- **What:** `dangerouslySetInnerHTML={{ __html: JSON.stringify(schema) }}` — every sibling (`:61`, `:118`, `:173`, `:225`) appends `.replace(/</g, '\\u003c')`. Checked character by character: in JS source `'\\u003c'` is the six literal characters `<`, a valid JSON string escape for `<`, so the escape in the other four **is** correct and does block `</script>` breakout.
- **Why it matters:** Not currently exploitable — `BreadcrumbJsonLd` and `WebPageJsonLd` have zero call sites. But `items[].name` is exactly the kind of value that comes from a CMS title, so the first caller added gets a breakout for free.
- **Fix:** Add the same escape, or extract one shared `<JsonLdScript schema={…}>` so it cannot be forgotten again.

### [Low] SEC-15 — Newsletter subscriber list readable and deletable by any authenticated user
- **Where:** `payload/collections/NewsletterSubscriber.ts:32-38` — all five operations are `authenticated`
- **Why it matters:** The collection's own header comment says it "stays locked to admins/editors, same pattern as `MemberProject`" — but `MemberProject` uses `authenticatedEditor`/`authenticatedAdmin`. ### [Low] SEC-16 — Google Drive folder name is interpolated into a Drive query string

### [Low] SEC-18 — Seed creates a known-credential admin outside production

### [Low] SEC-19 — MongoDB runs without authentication

### [Low] SEC-20 — `isAdmin`/`isEditor` field `condition` reads the edited document, not the viewer

### [Low] SEC-21 — Live credentials sitting in the working tree

### [High] A11Y-2 — The donation form's only error handling is a disabled button (WCAG 3.3.1, Level A)

## What was not verified

Stated plainly, because an audit that does not say what it could not check is not much use.

- **Nothing was executed against a running application.** `tsc`, `eslint` and `prettier` were run for real (results in the toolchain table), but no server was started, no HTTP request was issued and no database was queried. Every *finding* is from static reading except QUA-30. In particular, SEC-2 and SEO-2 rest on Payload's documented `_status` semantics rather than an observed response, and SEO-1's status code was inferred from the absence of `notFound()`.
- **`vitest run` and `next build` could not be run.** `node_modules` was installed on macOS and the shell available here is linux-aarch64, so rolldown's native binding does not resolve. The test suite's actual pass/fail state is unknown — which matters, because QUA-12 is independent evidence that CI may not be running it meaningfully either. **Run both locally before acting on this report.**
- **Whether the `map.tsx` lint errors predate the uncommitted changes.** `git diff --stat` shows that file is modified; a clean checkout of `HEAD` was not linted separately, so QUA-30 does not establish whether the errors are new or pre-existing.
- **Payload internals.** `node_modules` was not readable, so the following could not be confirmed from source: that the default for an unspecified access key is `Boolean(user)` rather than public (this moves SEC-5 between Medium and Critical); that `beforeLogin` runs only after successful password verification (SEC-8); whether field-level `access` on an unnamed `collapsible` is honoured at all; the default for `jobs.access.run`, which `payload/jobs/index.ts` leaves unset while exposing `/api/payload-jobs/run`; and whether `graphQL.disablePlaygroundInProduction` still defaults to `true`.
- **Whether the production `PAYLOAD_SECRET` equals the 7-character dev value** — it comes from a GitHub secret. Likewise whether branch protection makes `check` a required status check; if it is not, the entire CI story reduces to "runs after the merge, then deploys".
- **Bundle sizes.** No build or analyzer run was possible. PERF-3 and PERF-4 are structural certainties from the import graph; any KB figures would be estimates, so none are quoted.
- **Runtime infrastructure.** Whether `limit_req_zone mylimit` and `proxy_cache_path assets_cache` are declared in the host `nginx.conf`; whether `mongod` binds `127.0.0.1` or `0.0.0.0`; whether the deployed nginx config matches the one in the repo (`deploy.yml:105-109` notes it can exist untracked on the server, which is its own drift risk).
- **Mongo indexes.** The `where` clauses on `date`/`startDate`/`slug`/`is_confirmed` were read, but no index definitions exist in the Payload configs and the database was not inspected. Unindexed range scans on `hawk_events` and `contributions` are plausible but unconfirmed.
- **Rendered contrast in composited contexts.** Ratios were computed only where literal hex/oklch values could be read against a literal background. Combinations involving `opacity`, `color-mix()` or `backdrop-blur` were estimated by alpha compositing, and text over editor-controlled photographic hero backgrounds cannot be computed statically at all.
- **Screen-reader behaviour.** No NVDA/VoiceOver/axe run; all a11y findings are from source inspection.
- **Roughly 30 of the 45 page-builder blocks** were not individually opened. The heading, image, form, carousel and map blocks were read in depth, plus every block matching the hardcoded-string and `alt=` sweeps. `StatsBlock`, `TimelineBlock`, `PricingTableBlock`, `OfferCatalogBlock`, `StepsBlock`, `SocialProofBlock`, `ResourceDownloadBlock`, `QuoteHighlightBlock`, `GrowthVisionBlock`, `WhyHereWhyNowBlock` and others may hold issues the greps did not pattern-match.

- **Dead translation keys.** A static pass flagged 483 unreferenced leaf keys, but spot-checking showed most are composed dynamically (`` t(`roles.${role}`) ``, `` t(`languages.${project.language}`) ``). Only about eight were confirmed genuinely unreferenced — too few to file as a finding.
